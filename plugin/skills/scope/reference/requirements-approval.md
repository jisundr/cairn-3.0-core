# Grooming REQUIREMENTS.md to approval

Full `cairn:requirements` shape — load `Skill(skill: "cairn:requirements")` for the section definitions — never the old thinner form. Source what's already resolved: Problem and Goals from `goal`, Non-goals from `out_of_scope`, Success criteria from `done_when`; a supplied task file (ticket, Slack thread, doc) seeds Problem/Goals/Constraints further. When the project has a PRD (`.harness/workflow.md`'s Docs map, else `docs/product/PRD.md`), find the feature this task slices: it seeds Goals and Non-goals, and Problem cites it by name. Stakeholders, Constraints & assumptions, and Open questions rarely come from the record alone — check the codebase or conversation first, and ask via `AskUserQuestion` only for a genuine remaining gap, one question at a time, same style as `reference/vague-request.md`.

No Open question stays unresolved when the doc is done — that section is empty, or the doc isn't finished yet. State the finished doc back in a few lines; after a split, or a change to it or to a `depends_on`, add the sequence heads-up from `reference/decomposition.md` to the same message, so approving the requirements also approves the order. Overwrite `STATE.md`'s `key_info` with `awaiting requirements approval` (per `cairn:shared`), and wait for the user's explicit approval before continuing to the next step (`planner`, on a `build` folder). On approval, overwrite `key_info` with the approval and the next step, e.g. "REQUIREMENTS.md approved. Next: planner." This is the first of the escalated path's two approval gates; the second is the plan itself, per `agents/planner.md`.

Dispatched unattended: no interview and no wait, per `reference/unattended.md` — write the doc from the record plus whatever a supplied task file or the codebase already answers, leave Open questions naming only what's genuinely missing, and continue immediately. A gap with no conservative reading writes `needs-human` to `STATE.md`'s `key_info` and stops, same as elsewhere on this path.
